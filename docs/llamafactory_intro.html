LLM 微调 · 技术介绍（专业版）

用 LLaMA-Factory 做 SFT：
把代码大模型对齐为 SWE Agent 的工具调用协议

一个在免费 GPU（Colab T4，14.5G）上完成的端到端 SFT（Supervised Fine-Tuning，监督微调）实验：基座为 DeepSeek-Coder-7B，采用 QLoRA（4bit 量化的 LoRA），把「通用代码 LLM」对齐（alignment）为「能按 ReAct 协议输出工具调用的 Agent 基座」。下文先建立术语体系，再用真实数据流与配置讲清每一步。

一、术语体系（先看这节，后面全是这些词）

预训练 → SFT → 对齐

Pre-training：在海量无标注语料上做自监督（预测下一个 token），得到「懂语言/懂代码」的基座。SFT：在「指令-回答」标注对上做有监督训练，教模型按人类期望的格式与行为作答。本实验就是一次 SFT，目标是对齐到 Agent 协议。

📌 预训练 = 通识教育；SFT = 岗前培训，教具体工作流程与汇报格式。

PEFT / LoRA / QLoRA

PEFT（参数高效微调）：只训一小部分参数。LoRA 冻结原权重 W，注入低秩分解 ΔW=BA 只训 A,B。QLoRA = LoRA + 4bit 量化基座，把 7B 压进消费级显存。

📌 全参微调=重造手机；LoRA=装 App；QLoRA=在低端机上也能装。

灾难性遗忘 & 量化

灾难性遗忘：小数据全参微调会冲掉基座原有能力。LoRA 冻结基座可天然规避。4bit NF4 量化（bitsandbytes）：权重用 4 比特存储，配合 double quantization，显存降 ~4×，精度损失可控。

Agent / ReAct / SWE-bench

ReAct 范式：Reason（推理）+ Act（行动）交替。Agent 输出 Action+ActionInput(JSON)，由外部执行器调用工具。SWE-bench：给真实 GitHub issue，评「能否修好（resolve）」的权威榜。

📌 Agent=真人工程师的闭环；本实验训练的是「会正确填写工单/下达指令」的那一步。

二、任务定义：一次「协议对齐」式 SFT

输入是一条软件缺陷报告（issue 文本）。期望输出不是自然语言分析，而是可被 Agent 执行器直接解析的结构化动作：

# 期望输出（微调后的真实样本）
Action: analyze_issue
ActionInput: {"instance_id": "django__django-14559", "repo": "django/django"}

这本质是让模型学会一种领域特定的序列化协议（tool-calling schema）：在给定 issue 时，以高概率生成 Action: 前缀与合法 JSON，而非开放域文本。训练信号就来自「正确动作序列」的监督。

三、实验流程（含真实数据与配置）

3.1 数据工程：从轨迹到 ShareGPT 样本

源数据来自 SWE-bench_Verified 的成功修复轨迹，整理为 ShareGPT 格式（conversations 含 human/gpt 轮）。一条训练样本长这样：

{
  "conversations": [
    {"from": "human",
     "value": "Issue: bulk_update() 在 nullable 字段上抛 TypeError ...（problem_statement）"},
    {"from": "gpt",
     "value": "Action: analyze_issue\nActionInput: {\"instance_id\":\"django__django-14559\",\"repo\":\"django/django\"}"}
  ]
}

规模：训练集 235 条成功轨迹；另留 20 条 held-out（同分布、seed=42 固定）作为评估集，训练时完全不可见，防止数据泄漏导致的虚高指标。

3.2 训练配置（LLaMA-Factory YAML 关键字段）

# llamafactory_runs/sft_v1/sft_config.yaml（节选）
model_name_or_path: deepseek-ai/deepseek-coder-7b-instruct
finetuning_type: lora            # PEFT 方法
quantization_bit: 4             # QLoRA: NF4 + double quant
lora_rank: 16                  # 低秩维度 r
lora_alpha: 32                 # 缩放因子，通常 = 2×rank
lora_dropout: 0.05              # 正则，抑制小样本过拟合
cutoff_len: 2048                # 单样本最大 token 长度（上下文窗口）
num_train_epochs: 3              # 遍历训练集 3 遍
per_device_train_batch_size: 1    # T4 显存受限
gradient_accumulation_steps: 8   # 等效 batch=8，稳训练
learning_rate: 2e-4              # LoRA 常用较大 lr
lr_scheduler_type: cosine         # 余弦退火
gradient_checkpointing: true       # 用算力换显存

3.3 LoRA 的数学直觉

原线性层计算 h = Wx，W ∈ ℝ^{d×d}。LoRA 冻结 W，改为：

h = Wx + ΔW·x = Wx + B·A·x  (A∈ℝ^{r×d}, B∈ℝ^{d×r}, r≪d)

可训练参数量从 d² 降到 2·d·r。以 d=4096、r=16 为例：全参约 1678 万 → LoRA 仅约 13 万（≈0.8%），显存与训练成本降一个数量级，且原能力因 W 冻结而不被覆盖（规避灾难性遗忘）。

3.4 训练执行与监控

环境：Colab T4（14.5G）。策略：4bit QLoRA + batch=1 + 串行加载（BASE 推理完即 del+empty_cache() 再载 FT），规避 OOM。

时长：~80 min，最终 train_loss = 0.80（交叉熵损失，越低代表对「正确动作序列」的拟合越好）。

# 启动（已沉淀为脚本）
llamafactory-cli train \
  llamafactory_runs/sft_v1/sft_config.yaml

产物：adapter_model.safetensors（~160MB）+ adapter_config.json，已备份 Drive。

3.5 评估：held-out 上的 agent 动作合规率

指标 agent_rate：输出同时含 Action: 且其后 ActionInput 为可解析 JSON 的比例。判定逻辑（节选）：

def is_agent_action(text):
    if not text or "Action:" not in text: return False
    m = re.search(r"ActionInput:\s*(\{.*\})", text, re.DOTALL)
    if not m: return False
    try: json.loads(m.group(1)); return True   # JSON 可解析才算合规
    except: return False
推理前提（关键）：生成必须套 apply_chat_template 注入 DeepSeek 的 special tokens 与对话结构，再截断只取新生成部分（out[0][in_len:]），max_new_tokens=768、do_sample=False（贪心解码，保证可复现）。否则 tokenizer 缺失模板，模型退化为「回声」输入。

五、踩坑与根因（工程判断力）

① 评估假象：未套 chat template

初版直接 tok(prompt) 生成，缺失 special tokens 与角色标记，模型退化为前缀复述（prefix echo）——BASE/FT 输出与输入一致，早期 composite 指标 0.453 vs 0.446 是噪声。根因：tokenizer 没注入对话结构，生成条件被污染。

修正：apply_chat_template + 截断新生成 + 贪心解码 → 暴露真实分布差异。

② OOM 与显存编排

T4 14.5G 放不下两个 7B。根因：同时驻留 BASE+FT。解法是串行生命周期（用后即 del+torch.cuda.empty_cache()），并用 4bit + gradient checkpointing 用算力换显存。

③ 权重丢失→重训

首训只备份测试集，权重随会话销毁。沉淀为「训完即 copytree 到 Drive」流程，保证可复现。

④ 4bit 是 T4 的硬约束

缺 quantization_bit:4 时 7B fp16 直接 OOM（曾因残留进程占 3.93G 触发）。QLoRA 是免费卡的必选项，非可选项。

六、诚实的边界（面试加分项）

定位：这是一次协议对齐（behavior alignment） Proof-of-Concept，而非「模型能端到端修 bug」的结论。
  • 评估粒度：仅在 20 条 held-out 上测「首动作格式合规」，属同分布格式对齐，未测多轮规划质量。
  • 未跑 resolve：要得官方 resolved_rate，需接入 Agent 图（checkout 仓库→apply→跑 FAIL_TO_PASS）。项目预留 live 评估接口，Colab 上未执行。
  • 样本量：235 训练 / 20 测试偏小，r=16 在小数据上仍有过拟合风险（靠 dropout+早停缓解）。扩大测试到 50–100 条更稳。
  • 真实价值：证明极低成本（免费 GPU + QLoRA）即可把通用代码模型教会 Agent 行为模式，是一条可复现、可扩展（换基座/加 DPO/GRPO）的路径。
