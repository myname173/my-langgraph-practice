01

问题定位

记忆库原本是一个模块级 dict 单例 _memory_bank，只活在进程内存里。长任务（尤其是跑到一半被中断、随后恢复的那种）一旦换进程，风格记忆就直接清零。

后果是隐性的：恢复后的 film_studio 拿到空的风格上下文，get_previous_scene_style() 返回 None，后续镜头照常生成、也不报错——但镜头之间的视觉语言已经在无人察觉的情况下漂移了。这类退化没有任何日志告警，属于最难排查的一类。

同时审计的一项

reference_embeddings（角色一致性向量）经核查已经在 MultimediaState 通道里，随 SqliteSaver 快照持久化（graph 写入 / qc 消费），且 embedding.py 无模块级值缓存——本项无需改动。

02

修复语义

采用「线程作用域 + 写即落盘 + 缓存层」的三层结构，保持原有 API 语义不变，只把作用域从「全局单例」收窄到「线程」。

  1. 按线程分片
    记忆库按 thread_id 隔离，落盘到 data/memory/<thread_id>.json；不同任务线程互不可见。
  2. 写入即原子落盘
    每次 record_scene_style() 后写临时文件再 rename 替换，杜绝半截文件；落盘失败仅告警、不阻断主流程。
  3. 首次访问自动重建
    新进程第一次读某线程记忆时，发现缓存未加载即从磁盘 JSON 重建——这正是「中断恢复」场景的核心修复点。
  4. 新 run 按线程清空
    reset_memory(thread_id) 在新 run 开始时同时清缓存与落盘文件；恢复中断线程不走该节点，记忆因此得以保留。

模块级 dict 退化为进程内缓存层，磁盘才是事实来源。reference_embeddings 的审计结论见上一节。

05

影响与下一步

影响

从「进程内存」升级为「磁盘持久」后，长任务中断恢复不再丢风格上下文；单次额外 IO 与主流程耗时可忽略，且落盘失败自动降级为空记忆，不引入新的失败面。

边界

并行模式（P0-2）下 film_studio 在扇出前仅运行一次，记忆库因此只记录一次规划快照——这是既有文档化降级，与持久化正交，本次未改变。

P0 层至此四项全部落地（三档质量 / 镜头并行 / 熔断台账 / 记忆持久化）。建议的后续：先在有小额免费额度时做一次真实 2 镜头冒烟，再推进 P1-1 首尾帧链式衔接。
